# Решения и их причины

## Про счёт
- Брокер Tradernet / Freedom Broker, счёт в USD.
- Часть бумаг (тикеры `_KZ.KZ`, биржа KASE) может быть переведена от прошлого брокера.
  Дата перевода через API не видна. Позиции, закрытые у прошлого брокера, в API
  отсутствуют — история «All» — это история этого счёта, а не всех инвестиций.
- Могут быть облигации биржи AIX (тикер вида `XXXXXX.MMYY.AIX.KZ`), цена в % от номинала 100.
- Ключ API — только чтение, торговля выключена.
- Часовой пояс пользователя может отличаться от US; даты торговых дней берутся из свечей.

## Методология
- **Доходность взвешена по времени (TWR)** — чтобы пополнения не искажали процент и
  результат можно было честно сравнивать с индексами.
- **Состав счёта восстанавливается по дням по сделкам**, а не «текущие позиции × рост
  цены» (как у Yahoo). Реальный результат счёта — наш вариант. Взгляд Yahoo («как сыграл текущий состав») — возможная
  будущая доп. линия на графике.
- **Бенчмарки — ETF SPY и QQQ** (а не индексы) для расчёта доходности: так честнее при
  сравнении с реальным портфелем. В полосе рынков — сами индексы `SP500.IDX`,
  `NASDAQ.IDX`.
- **US — по закрытию основной сессии, как Yahoo (владелец, 2026-11-01, Task 51).** Изменение за
  день и цены концов периодов (база и конец Performance / Contributions / Holdings Period, база и
  конец графиков карточки) у бумаг US считаются по закрытию основной сессии (16:00 Нью-Йорк), а не
  по последней сделке расширенной сессии. Сделка после закрытия / до открытия показывается
  отдельной строкой в карточке («After hours» / «Pre-market»). В Holdings пост-маркета нет (YAGNI).
  Остальные рынки — без изменений. Правило и источники — docs/CALCULATIONS.md.
- **Nasdaq = Nasdaq-100**, не Composite.
- **Нефть/золото/серебро — через ETF** (USO, GLD, SLV): спота и фьючерсов у брокера нет.
  На карточках это подписано; % за день почти совпадает с сырьём, цена — цена ETF.
- **Периоды длиннее срока жизни счёта обрезаются до даты открытия**. Для молодого счёта 6M / YTD /
  1Y / 5Y / ALL совпадают.
- **Цвет графика — по нарисованной линии**, а не по знаку доходности. Был баг: график
  стоимости рос за счёт пополнений, а красился в красный из-за отрицательной TWR.

## Интерфейс
- Светлая тема по умолчанию; тёмная «как Bloomberg» была отклонена из-за контраста.
- Моноширинные цифры и янтарные подписи — остатки «терминального» стиля, понравились.
- По умолчанию период YTD.
- Скрытие сумм — обязательная функция (показывает экран другим людям).
- **Полоса под статус-баром iPhone (2026-11-01).** В iOS 26 / Safari 26 `theme-color` больше не
  красит панели. Safari, и в обычном режиме, и «на экране Домой», берёт цвет фона у fixed/sticky
  элемента, который касается верхнего края, и закрашивает им полосу под статус-баром или
  компактной панелью вкладок. Когда элемент уходит, Safari часто оставляет последний цвет. Без
  таких элементов цвет берётся из фона страницы. У нас так «залипал» цвет карточки от
  sticky-заголовка Holdings. Первая попытка (Task 36): на телефонах fixed-полоса `body::before`
  цвета `--c-bg` высотой safe-area + 12px, а sticky-заголовки прилипали под ней. На iPhone не
  сработало: под часами по-прежнему был виден прокрученный контент, а полоса оказалась ниже зоны
  статус-бара. Вывод по скриншоту: в Home Screen режиме `env(safe-area-inset-top)` = 0, зона
  статус-бара лежит вне layout viewport, и iOS полосу не выбрал. Вероятные причины:
  `pointer-events: none` (краевой элемент, судя по всему, ищется hit-test'ом, а такой элемент
  hit-test пропускает) и/или малая высота. Заголовок Holdings (~32px, hit-testable) до Task 36
  выбирался. Решение (Task 39): полосу убрали, sticky-элементы снова `top: 0`. Пока заголовок
  Holdings прилип (IntersectionObserver-сентинел у его естественного верха → класс `is-stuck`,
  без scroll-листенеров; включается за 8px до края), на телефонах он становится непрозрачной
  панелью `--c-bg` во всю ширину экрана (выходит за поля и рамку карточки, высота прежняя,
  колонки на месте). Тогда iOS тянет в статус-бар цвет страницы, и «запомненный» цвет после
  ухода заголовка тоже цвет страницы. Не прилип — обычный вид в карточке. Бар карточки бумаги
  (`.pcard__bar`) и так `--c-bg`; на телефонах он тоже растянут на всю ширину. Ограничение: выше
  Holdings, до первого прилипания, iOS может показывать под часами прокручиваемый контент
  (поведение iOS по умолчанию). Шире 48rem ничего не меняется: там заголовки не прилипают к
  окну. Кроме того: тему до первого кадра ставит внешний
  `public/theme-boot.js` (CSP запрещает inline), `html` получает фон `--c-bg` (оверскролл,
  сэмплинг). Цвета фона заданы в трёх местах: `THEME_BG`, `--c-bg` и boot-скрипт; тест сверяет,
  что они совпадают. `apple-mobile-web-app-status-bar-style` оставлен `default`. Владелец
  проверил: в standalone статус-бар и так сливается с фоном. `black-translucent` даёт белый
  текст, его не прочесть в светлой теме. Манифест статичен, тему в нём не учесть, поэтому
  `background_color`/`theme_color` = тёмный фон `#0D0F0E`: короткий тёмный сплэш перед светлой
  темой заметен меньше, чем белая вспышка перед тёмной. Вариант Task 39 на iPhone ещё не
  проверен, только на headless-эмуляции.
  Источники: [WebKit 301756](https://bugs.webkit.org/show_bug.cgi?id=301756) (ответ WebKit: тинт
  тянется от fixed/sticky элементов у края с перекрытым инсетом),
  [WebKit 305546](https://bugs.webkit.org/show_bug.cgi?id=305546) (fixed-элемент сверху задаёт
  цвет статус-бара, в т.ч. в Home Screen apps; theme-color не влияет),
  [Ben Frain](https://benfrain.com/ios26-safari-theme-color-tab-tinting-with-fixed-position-elements/),
  [restore-meta-theme-color demo](https://ios-safari-restore-meta-theme-color.pages.dev/)
  (полоса 12px у края; без неё UI держит последний цвет).

## Загрузка и данные
- Данные должны быть **живыми**; суточные снимки отклонены.
- **Никакого захардкоженного списка бумаг** — только динамически из позиций и сделок.
- Первая загрузка в старом дашборде была медленной (две волны запросов по несколько
  секунд) — главная мотивация приложения с локальным кэшем.
- **Кэш переживает релизы** (2026-11-01): у каждой записи IndexedDB есть версия формата
  (`CACHE_VERSION` в `config.js`). Запись другой версии считается отсутствующей: данные с TTL
  перезапрашиваются сразу, история свечей скачивается заново один раз. Повод: после релиза
  строки старого формата жили до конца TTL, и графики EU 5 минут были пустыми.
- **История свечей неизменна**: без TTL; при докачке перезапрашиваются только последние 2
  сохранённых дня (последний мог быть сохранён до закрытия сессии).
- **Сплиты и корректировки**: при докачке закрытие самого раннего общего (сохранённого и
  пришедшего) дня сравнивается с ответом брокера; расхождение больше 0.5% — вся история тикера
  удаляется и скачивается заново одним запросом. Коэффициенты сплитов нигде не зашиты.

## Известные ограничения и идеи на будущее
- Статус рынка (открыт / закрыт) — поле `s` брокера из подписки WS `markets` (REST
  `getMarketStatus` — запасной путь); праздники брокер учитывает в нём сам. Список праздничных
  дат из подписки приложение не использует: торговый день берётся по барам `SP500.IDX`.
- Время рынка — по часам брокера (Task 25), без зашитого сдвига: смещение сервера (UTC+3) — по
  дневным свечам, часы рынка, `dt` и зона — из `getHloc` `info[t].mrkt`. Перевод часов в США
  1 ноября 2026 меняет `o` / `dt` FIX (16:30 → 17:30, 420 → 480) в ответе брокера; проверить
  на живой сессии после перевода.
- Запрос движения денег (take=500) медленный, а нужен в основном для даты открытия
  счёта — можно кэшировать бессрочно и докачивать новое.
- Идея: доп. линия «текущий состав, как будто держали весь период» (взгляд Yahoo).
- Идея: разбивка по классам активов (акции/ETF/облигации), таблица сделок периода.
